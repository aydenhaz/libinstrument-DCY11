# Unsafe legacy Fragment factory isolation (2026-10-21)

Concrete corruption in the previous source: Fragments.h declared ten classes with no data members or bases, so allocations in Fragments.cpp/Fragments_batch4.cpp created one-byte objects. The A106 factory immediately passed such an allocation to BaseCtor, which performed memset(self,0,0x80) and two strncpy writes at +0x10 and +0x40. This exceeds the allocation regardless of runtime navigation state. Other factories cast similarly empty objects to CGFragment*, or returned null while claiming original BX LR instructions represented null-return factories. Neither is a reconstructed host factory.

The host CGFragment itself has a constructor taking CGFragment::ELaunchMode, exported at 0x294381, multiple subobject vptrs and state extending hundreds of bytes. The prior interface-only CGFragment header implicitly allowed a one-byte new CGFragment() with no host constructor. Four Batch20 fallback paths used it before invoking host methods. Evidence host_fragment_ctor_294380.txt shows actual host construction; this audit does not claim the complete base layout is now recovered.

Changes: archive the two legacy factory implementation files under rejected/unsafe_*.cpp.txt and remove their executable bodies, including the overflow helper and invalid shared stub interpretations. Keep declaration names unresolved rather than supplying null/no-op replacements. Delete default constructors for all ten placeholder classes and the CGFragment interface projection. The four Batch20 fallback allocations now explicitly reference undefined createFragmentUnrecovered; their correct concrete factory/type identity is still outstanding. These missing symbols must not be provided by fake stubs to satisfy the linker.

Validation: ARM compile-time contract rejects default construction of CGFragment and all ten placeholder types. Full ARM Linux musl compile-only passes 39/39. This count measures translation units, not recovery completeness; two factory translation units now intentionally have no definitions. Source search confirms no remaining executable new CGFragment()/new placeholder concrete fragment in internal sources. No native crash reproduction, Android strict-link pass, true factory implementation or replacement SO is claimed. Other legacy layouts and business bodies remain incomplete.
