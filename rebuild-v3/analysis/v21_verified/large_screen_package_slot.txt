LargeScreenImpl package-receiver slot — V21 static trace

`LargeScreenImpl::OnChangeScreenMode` (`sub_2e0f8`) does not use its own
`this` as a `CGPackage`. Its Thumb dispatch branches load a package pointer
from one shared position-relative data slot at image RVA `0x6fd48`, then pass
that pointer as r0 to the host instance methods
`CGPackage::getHostFragmentActivity()` and `CGPackage::getContext()`.
`CGFragment::tryStartExistFragment(...)` is then called with the returned
activity object as r0. The relevant reads are at `0x2e20e`, `0x2e2fa`,
`0x2e36e`, and `0x2e3ea`.

An independent call path at `0x158aa` also loads the pointer slot at RVA
`0x6fd48` and then calls the same two instance methods. This confirms the
receiver is shared module state, not `LargeScreenImpl::this` and not a context
parameter. The exact GFrame instance-method ABI is recorded in
`analysis/PACKAGE_RECEIVER_ABI.md`.

The slot is in the original DSO's BSS. Factory `0x2eb08` writes its newly
constructed Packet into this exact slot at `0x2eb48`: the literal loaded
at `0x2eb44` is `0x411fe`, and the PC observed by the `0x2eb46` ADD is
`0x2eb4a`, yielding `0x6fd48`. This identifies the receiver as the
Packet's host CGPackage base at offset zero, published after the constructor
and four derived vptr stores. The original initializer at `0x14e40`
registers this factory.

A replacement DSO has its own BSS and cannot reuse the original RVA. Its
Packet factory and host base must be built before the `Unrecovered` calls can
become real member calls. No source shim or arbitrary cast is justified by
this evidence. See `packet_factory_runtime_table.md` and
`tools/inspect_packet_factory.py --check-v21`.
